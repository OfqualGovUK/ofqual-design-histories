## Context

A UI shell is a consistent application of header, footer, global navigation components and screen regions. The platform's UI shell must:
- Allow users to navigate easily between products and pages.
- Improve efficiency through establishing predictability and familiarity.
- Provide navigation reference points and orientation.
- Provide flexibility to implement product-specific navigation and functionality.
- Maximise available screen space for information dense layouts. 

## Options

### App switcher, local product left navigation, global header

The initial shell concept utilised most of Carbon design system's available UI shell components. The intention was to provide product navigation using the app switcher pattern. The global header contained cross-platform functionality such as user profile, notifications and app switcher. Product-level navigation used a left hand navigation menu that was collapsible and contained items to navigate different views (Figure 1).

![Wireframe showing the UI shell components: Global header, app switcher and left hand navigation](picture1.png)

The use of left hand navigation is common in enterprise applications and is a pattern users in Ofqual are familiar with. However, the combination of app switcher, left hand navigation and global header created a very busy interface that reduced the available screen space for content. 

The left hand navigation also conflicted with the need for a secondary level of navigation within products. Likely requiring the use of navigational tabs for product-level navigation, which would add further complexity to the interface (See Figure 2).

![Wireframe showing the use of tabs for product-level navigation](picture2.png)

The app switcher also relied on an overlay (contrary to our intended design principles) and in early testing it was found to be confusing for users.

Finally as the concept of the platform and functional requirements for a minimum viable product evolved, it become clear that both the left hand navigation and app switcher were not necessary and a simplified approach could be taken.

### Removing global left hand navigation

The next iteration on the concept removed the left hand navigation as a product-level navigation element, to facilitate the use of a left hand navigation component instead of tabs for local navigation, in this case to navigate around the functionality of a case (Figure 3). 

![Wireframe showing global header, app switcher and local-level left hand navigation replacing tabs](picture3.png)

This was further simplified to remove the need for the app switcher component, instead using links in the global header to navigate the platform (Figure 4).

![Wireframe showing global header with links to navigate the platform and local-level left hand navigation](picture4.png)

## Proposed solution

Further refinement of MVP functionality and user needs has led to the current (highly simplified) design of the UI shell. The global header contains links to navigate between the main areas of the platform - Cases, Profiles (which will be entity level views). 

For the purpose of the high fidelity prototype, user profile and notifications functionality are omitted for now (later work to cover these requirements). In their place in the header is a prototype settings control that facilitates the seeding of data into the prototype for user testing purposes, and the clearing of session data storage to revert prototype states if required (Figure 5).

![Screenshot of coded prototype showing the UI shell consisting of global header with links to navigate the platform. Also shown is the local-level left hand navigation for cases](picture5.png)

## Research

The first round of user research testing focused on core patterns and concepts in case management. Therefore global platform navigation was not a focus at this stage. However, there were some findings that are relevant to the UI shell design:

- Participants weren’t sure of the difference between ‘Ofqual Cases’ and ‘Cases’ in the app header. This is a product naming / logo issue that needs to be resolved.
- The left hand navigation for case-level functionality was well understood by users.
- The ‘Profiles’ label was misunderstood by some users, who expected it to relate to user profiles. This is a labelling or grouping information architecture issue that needs to be resolved.

## Next steps

1. Footer design to be added to the UI shell.
2. Information architecture work to resolve global navigational or labelling issues.
3. Entity-level views to be designed and prototyped and included into the navigation ready for further UI shell testing.
4. Prototype refactor to use a common UI shell component across all views.
